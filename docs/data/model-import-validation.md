# Real ForceOrg import validation

Validated 2026-10-15 on Windows with Godot 4.7.2. The user explicitly authorized downloading/installing ForceOrg as necessary to test real model imports. No TTS cache was found in the standard Documents/OneDrive paths, and TTS was absent from the inspected standard Steam library. Installing TTS or running the downloader EXE was unnecessary: the official downloader documents a manual save download, which was used directly.

Three meshes and two shared/distinct texture files were downloaded from the save's own Steam content references. Meshes tested: **Primaris Intercessor Sgt**, **Primaris Intercessor**, and **necron warrior reaper / component 1**. Marine mesh sizes were 332,864 and 331,780 bytes; the Necron component was 1,101,919 bytes. Credits/source descriptions are retained in catalog entries and local mapping metadata. Source save, manifests, downloads, logs and screenshots remain in `.tools/forceorg-real`, ignored by Git and excluded from the distributed project content.

## Defects found and corrected

1. The original scanner saw mostly table/base objects. Added a bounded parser for JSON long-string literals in ForceOrg's `objectJSONs` tables. It does not execute Lua; computed expressions are rejected and warnings are shown.
2. Actual miniature components can live in `ChildObjects`, while the parent mesh is only a base. Added child traversal, inherited names/credits and explicit component identities. At this stage components could be selected individually; the bounded automatic composite assembly described in the 30 October audit was added later.
3. Once these records were expanded, the real collection exceeded the previous 20,000-record limit. Raised the bounded object limit to 100,000 while retaining file/extracted-data byte limits.
4. The expanded catalog needs search. Added model-name filtering, capped displayed matches at 200 and preserved original entry indices/identity after filtering.
5. A real texture was JPEG content saved under a `.png` cache name. Replaced extension-based image loading with PNG/JPEG/WebP content detection, also supporting extensionless image files.

## Passed checks

- Real save scan and name-based selection, including static catalogs and child components.
- Unique local URL-derived cache matching, OBJ parsing and texture decoding for all three samples.
- Preview rendering, application to the unit definition and actual board rendering; match state remains unchanged by visual mappings.
- Save/reload of Marine and Necron mappings; a fresh main-scene launch automatically displays both imported unit types.
- Six portable local suites: static ForceOrg catalog, local models, cache lookup, allocation practice, gameplay layout and guided attacks.
- One host/client loopback allocation scenario with disconnect/rejoin while the actual local model profile was available.
- Graphical preview and board screenshots visually inspected at 1280x800.

The local default game profile (`user://local-models.cfg`) now references the tested Marine/Necron files and cache folder. Any existing profile would be copied into the local test directory before replacement; none existed on the first installation. Practice exercises use these visuals on the next ordinary launch. Local files must remain available, or placeholders will be used. Visual weapon/sculpt choice is independent of the practice army's equipped weapon rules.

## Limits

These 15 October checks proved the OBJ/image path for three samples, not every ForceOrg entry. At that time full composite assembly was unsupported. The 30 October audit below verifies assemblies whose static child components provide compatible OBJ and diffuse files. Later work added MTL/multiple materials, normal maps and a bounded static Unity AssetBundle conversion subset; the separate bundle audit below records its measured coverage and limits. Animated/dynamic content and arbitrary Lua remain unsupported. The cache for the initial samples was assembled from the save references rather than generated by TTS, so other TTS cache conventions still need testing. Linux and separate-machine networking remain unverified. The initial sample test did not install a downloader or transfer third-party files to other players.

## Full 161-profile Space Marine visual audit — 30 October 2026

The Godot visual audit loaded the current ForceOrg snapshot and every current-reference Space Marine construction profile. It placed one representative per datasheet on each side of a local tabletop (161 profiles per side, 322 positions). This is a visual import table, not a rules-legal roster and not a claim that each datasheet's full model count was placed.

- ForceOrg snapshot SHA-256: `ED0B66DC0518F03EA746A485D2739DEB57EA2094117D552C02925983C3BCBA44`.
- Catalog scan: 32,256 asset entries, 10,605 static embedded objects and zero skipped-table warnings.
- Loaded and rendered: 161 of 161 profiles on both sides (322 positions), with no placeholders or import failures.
- The 24 profiles that previously had no safe automatic matcher result now use reviewed visual-only aliases or a same-category OBJ already present in the selected ForceOrg catalog. These links are visual substitutes, not claims that every named sculpt or variant is exact.
- Download/import failures after retrying compatible variants: 0.
- Base-ring fit: 153 profiles had a detected ring scaled to within 0.5 mm of the datasheet base; eight models without a detectable ring used height/hull normalization.
- All 153 detected-ring checks were within tolerance. A malformed Judiciar OBJ with a 13.9-inch horizontal bound was rejected; the automatic retry found a complete variant with a 39.8 mm detected base and fitted it to 40 mm.

The automatic batch first selected a Company Heroes variant whose mesh returned HTTP 404. It then tried the next exact compatible variant and linked it successfully. This verifies the match-scoped fallback path as well as the composite OBJ download/assembly path. The audit uses the existing user-local model cache and an isolated audit mapping; downloaded model files were not added to the repository.

The live Godot captures and per-profile table are in the ignored local folder `.tools/model-audit-161/` (`slice-1` through `slice-4` overviews and side-by-side detail captures, plus `report.md` and `report.tsv`). To keep memory bounded, each captured page renders up to 42 datasheets per side. The numeric base-ring checks measure diameter only; they do not certify every model's pose, facing, height, paint appearance, visibility geometry or event acceptance. The table used compatible OBJ meshes and reviewed visual aliases. Static AssetBundles now have a bounded conversion path; exact bundle coverage is measured separately below, and exact-sculpt coverage is still incomplete.

## Static Unity AssetBundle conversion audit — 31 October 2026

The bounded local converter was exercised against the bundle components selected by all 161 current Space Marine profiles in the same ForceOrg snapshot. This is a separate import-format audit; it does not claim the previous visual table used these converted bundles.

- ForceOrg snapshot SHA-256: `ED0B66DC0518F03EA746A485D2739DEB57EA2094117D552C02925983C3BCBA44`.
- Godot 4.7.2 on Windows, with the optional converter built using Python 3.12.14 and UnityPy 1.25.4.
- The 161 profile plans contained 50 bundle-component references across 45 unique bundle URLs and 42 profiles.
- All 45 of 45 unique URLs converted and passed Godot OBJ-part/composite validation; the bundles contain 406 rendered parts across 42 profiles. The latest pass reconverted all seven previously incomplete Judiciar components with matching secondary bundles and reported zero missing CAB/material dependencies. A simulated saved Judiciar mapping with old dependency warnings repaired automatically to 10 ready parts; the resulting cache resolved all 10 components on the next lookup.
- The Invictor Tactical Warsuit bundle imported 24 parts and the Wulfen Dreadnought bundle imported its 39 MB mesh after the bounded OBJ parser was raised to 1,000,000 attributes/triangle vertices; the measured largest cases used 627,114 attributes and 592,788 triangle vertices (Invictor) and 880,359 attributes and 484,932 triangle vertices (Wulfen). - Ancient converted with 14 parts. Godot validation reported 2,472 invalid UV references dropped and two material texture maps omitted for a part with no UVs; the runtime recomputes normals.

The refreshed matcher found 161/161 profiles ready, and all 2,051 catalogued visual variants across those profiles produced valid import plans. The refreshed bundle-conversion batch finished 45/45 with no conversion/import failures and no missing CAB/material warnings. Detailed local rows are in the ignored `.tools/model-audit-161/bundle-conversion-results.tsv`. Bundle inputs, generated OBJ/texture outputs and screenshots remain in ignored `.tools`/user-cache locations; none are committed or shipped. This evidence supports the bounded static subset only.
