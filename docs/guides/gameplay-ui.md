# Gameplay UI

The game opens on a dedicated title screen over the existing 3D battlefield. Its primary action is **Start tactical training** when no compatible local save exists; a compatible save adds **Continue saved match**. The training summary shows both catalog-derived totals and offers **Swap training sides**. **New match** opens the existing setup flow. Armies, Models and Tools remain available through secondary navigation when no match is active. During a match, the board is the primary workspace and contextual commands appear in a collapsible panel on its right edge. The menu, settings, help and battle log open separate overlays.

## Title screen and combat HUD

The interface uses 1920×1080 as its layout reference while preserving the project's 1280×800 initial window. The title screen is a Godot UI composition over the local procedural battlefield and any already imported local miniatures; it adds no generated artwork or model files. At launch, the menu intercepts board input. In a local match it also blocks board interactions while open. In LAN, opening the local menu does not pause or change the match state for either player.

The combat HUD stays above the board and remains fixed while details scroll. Its top bar is a turn rail: round and active player, then Command, Move, Shoot, Charge and Fight, with the current step marked. The line under the rail states who must act and the one thing to do. Score and connection stay on that rail. Guided play adds a compact step counter; the decision line remains the instruction source. The selected-unit card shows owner, living-model count, the selected model's wounds, defense profile, effective OC and Battle-shock state; movement distance or an active action appears when relevant. The contextual Command panel carries the current choices, datasheet and results. It can be hidden with the HUD button to expand the board view and opens again when a unit is selected. Short actions include Begin move, Confirm move, Plan attacks and Continue. Longer rule explanations stay in Help. Disabled choices retain the validator's explanation. Scope warnings remain available from the HUD tooltip.

Full profiles, equipment, ability effects, mission state, raw dice and technical session data remain accessible through tooltips, the technical-details foldout, completed result details, dice tray and Battle log. The attack forecast remains conditional and separate from resolved damage and recorded dice. The HUD only presents engine state; it does not alter validators, host authority or game state.

The **Menu** action shows the in-match screen with **Return to current match**, **Settings**, and **Save match**. Workshop and training tools are unavailable until leaving the match. Returning closes the local overlay and preserves the current phase, selection and command panel. LAN continues while any local screen is open. Settings gather window mode, resolution, model wounds/status markers, board/camera motion, decision framing and dice animation. **Apply** saves local preferences; **Revert** returns to the last applied values. Sound controls are not shown until the game has audio. Saved-match resume availability is computed by the normal save compatibility checks for configuration, rules/data pack, state structure and journal integrity; merely finding a save file does not enable Continue.

The **Log** HUD button opens the persistent battle journal in a dedicated overlay. It retains the journal's paged events, state changes, results, per-model target assignments, attack pools and ordered D6 values with phase/player/revision context. This detail is reconstructed from the existing record patches; the save/journal format is unchanged. Closing it returns to the same match screen; viewing or paging sends no gameplay command. In LAN, the client reads pages from the host and the host remains responsible for saving. The dice tray labels faces as recorded D6 values; its brief reveal animates stored results and never creates a new roll.

## Guided first session (D1)

**Entry:** Title screen → **Start tactical training**. This starts the distinct [Fire and Manoeuvre / Close Assault forces](tactical-training.md) from the current local catalog; the player controls both sides. It uses the custom training mission, current unit abilities and admitted Core/Gladius stratagems. Optional phase tips and an experiment list point to leader abilities, CP stratagems, plasma/Hazardous and Bladeguard stance decisions without forcing a sequence. Automatic model downloads are off. It does not certify competitive balance, complete faction rules or army legality. The former 550-point mirror remains independently selectable.

| Moment | Player goal | In-game guidance and feedback |
|---|---|---|
| Mission setup | Resolve the selected mission's roll-offs and declarations | A compact HUD counter marks progress; the decision banner identifies the current choice and owner. Full step limits and term explanations are in Help. |
| Army setup | Confirm required leaders, Warlords, Support assignments and reserve declarations | Help explains the declarations and defines Leader, Warlord and Reserve. The next step stays gated until required choices are resolved. |
| Deployment | Place each unit and continue | Help explains the marked zone and preview positions. The board shows placement and count; incomplete or invalid placement cannot be confirmed. |
| Battle-start setup | Select a Terminator unit's optional Teleport Homer, set X/Z, confirm, or skip it | The guide states the marker → position → confirm sequence and offers **Finish start-of-battle declarations** to enter Command. |
| Movement | Select a friendly miniature, start a Normal move, reposition and confirm | The guide defines Normal move and confirmation, and states the boundary on legal movement. The decision banner and movement controls remain visible. |
| Shooting | Select a friendly unit, choose an eligible enemy, assign attacks and confirm | The guide defines eligible target and attack plan. Assignments are reviewed and validated before confirmation; the completed attack summary shows the result. |
| Charge | Select eligible targets, roll 2D6 and resolve any placement | The guide names the current charge task and waits on the existing target/placement decisions. |
| Fight | Follow the current pile-in, attack, reaction or consolidation step | The guide changes with the Fight step and points to the next required action. |
| End turn | Close the active player's turn and continue to the next player | The guide marks the first turn complete while the phase rail remains authoritative for later play. |
| Match end | Review the recorded result and history, or start another exercise | The guide offers the existing result and history paths. The sample does not certify full army legality or every rule. |

The step detail remains available in Help; the in-match HUD shows a compact guide counter next to the phase rail. Current ability-choice explanations remain visible in the Command panel during guided training. Phase progression and eligibility come from the match engine. Resuming the exact tactical formations restores contextual guidance from the saved phase, without storing a separate tutorial action sequence. Other matches retain their own configuration. The optional Homer step below applies to the former mirror and other Terminator exercises, not to the new tactical forces.

## Contextual weapon glossary (D2 pilot)

During an attack plan, hover a weapon/profile row or the selected profile control to read concise explanations for the profile's listed, recognized weapon abilities. The target selector explains that its current choices passed the attack planner's checks; the Lethal Hits choice explains the automatic-wound trade-off. Hover a movement type to see its eligibility and consequences, including Advance, the two Fall Back modes and remaining stationary. The Begin and Confirm movement controls explain when positions are committed. Charge and Fight placement controls explain the 2D6 charge roll, selected targets, pile-in and consolidation limits. Hover the phase banner or progression control for the current phase's purpose and Core Rules section. In the supported Battle-shock and Command Re-roll windows, the unit, die, accept and stratagem controls explain their choices, CP cost and applicable limits. Disabled movement, contact, attack, defense and objective controls retain the validator's reason and add the applicable Core Rules reference where one is defined. Help names the relevant 11e Core Rules section and includes a link to the reference.

The pilot covers only the weapon abilities the attack engine currently recognizes, the seven turn parts shown by this build, core movement/charge/Fight placement choices, selected blocked-action groups and the supported core-stratagem decision windows. It explains the rule term but does not claim that every effect is active in every match: match options and the implementation scope still govern resolution. Missing glossary entries are called out explicitly. A complete unit-ability and faction-stratagem glossary remains future work; each entry must match its selected Wahapedia 11e source/version and the implemented capability boundary.

**Rules boundary:** descriptions were checked against the June 2026 11th-edition Core Rules at [Wahapedia](https://wahapedia.ru/wh40k11ed/the-rules/core-rules/) and cross-checked against the [official Games Workshop Core Rules PDF](https://assets.warhammer-community.com/eng_01-06_warhammer40k_new40k_core_rules-was6fbu1ix-hfewhmxyiy.pdf). These summaries use §§01.07, 03, 04.01.03, 06.03, 07–12, 15.01–15.04 and 24.04–24.38 where applicable. No discrepancy was identified between the current 11e sources for this pilot. Older official 10e sources give Insane Bravery a different timing; those are superseded here and are not used. Faction-stratagem help remains outside this certification until its current source can be cross-checked. Later official updates may change the version boundary.

## Contextual actions

During Command, doctrine abilities use separate action, unit and doctrine selectors. **Captain ability · 0 CP** exposes Strategic Acumen separately from **Adaptive Strategy · stratagem**. The preview shows the selected action's actual CP cost, doctrine effect, duration and current unit doctrine; an already-active primary doctrine receives a no-additional-effect notice. The confirmation button repeats the action and cost. Browsing never submits a command. Other available abilities remain accessible through their own category, and only existing legal choices are offered. This presentation does not change doctrine availability, cost, timing or eligibility.

Play groups controls into Movement/coherency, Charge/contact placement, Attacks, Resolve attack/damage, Objective actions and Phase progression. Groups with no relevant controls are hidden.

During an attack draft only its group is displayed, including Confirm and Cancel. Pending movement, contact placement, coherency removal and attack/Hazardous allocation focus the corresponding group until that decision finishes. Other groups return after the pending decision is resolved. This changes presentation, not host validation or the rules protocol.

An unavailable action has a reason next to its group and on the disabled action's tooltip. Movement, attack planning, allocation and objective eligibility reuse rule validators. Charge/contact guidance follows the current eligibility checks. Completed exercises, missing peers and opponent-owned decisions identify the responsible state/player. Plan confirmation errors update as assignments change; a valid selection clears the old explanation. Available alternative actions in a group remain usable, for example declining Precision while no character is selected.

The **Direct Precision** button requires a selected character. A selection of -1 is reserved for the explicit **Do not use Precision** button, rather than accidentally accepting the decline through a button labeled as directing Precision.

## Guided attack and defense flow

Attack editing presents four steps: select a living model from the attacking unit; choose its weapon/profile, target and any fixed melee count; assign and repeat; review and confirm to roll dice. The review names the selected model/unit, counts assignments and distinct target units, and lists the resolution order from the first assignment to each target. Cancel discards the local draft. Weapon and target dropdowns preserve their selections on refresh and do not expand the sidebar to fit long names.

Pending Precision, defensive group order, damage and Hazardous choices show stage-specific instructions and the responsible player. An eligible-model dropdown names the unit, model ID and remaining wounds. Selecting an item only changes board selection; the existing confirm button applies the decision through host validation. Returning to the prompt clears selection without declining Precision. The explicit decline button remains available for Precision; other required choices cannot be cancelled. Opponent-owned choices disable the picker locally. No save/damage rolls are exposed ahead of the existing rules sequence.

Tests check draft review without state changes, correct/incorrect model selection, named eligible choices, explicit confirmation, prompt reset, save timing guidance, opponent ownership and stale panel hiding. ## Results and history

The latest local/host notice appears before the selection card and action controls. It is separate from the completed-result summary and historical events; a notice is not proof that an entire attack has finished.

The latest attack summary names each model and target assignment, grouped target damage and destroyed models, plus prevention and discarded excess when present. Expanded details expose the recorded final D6 faces by stage; they are the host/local resolver result, not a new simulated roll. The animation now holds each tile at a blank rolling face before revealing its recorded value and can be disabled in Settings. The battle log offers the full per-model assignment and attack pool record. Hazardous wounds lost by the attacker, prevented wounds and unallocated discarded wounds remain separate from defending-target losses. **Show combat history and dice** expands the existing detailed log. It starts collapsed, preserves expansion across refreshes, and preserves the reader's scroll position when history content has not changed. New history content still scrolls to the latest entries. ## Track D3 presentation pilot

The board can show an optional compact Wounds bar above each living model, with current/maximum Wounds and the selected model's effective OC, Battle-shocked and movement state. The bar color is accompanied by exact numbers, and the toggle tooltip spells out its green/amber/red thresholds; color is not the only signal. The toggle hides these tags when the board is crowded. During an attack draft, the UI uses the same prepared attack batches as the resolver to show each pool's damage range if every declared attack becomes one unsaved wound. It labels this as a conditional scenario, before saves and prevention; critical or extra hits, failed hits/wounds, saves and damage prevention can change the result. It is not a probability estimate or a rules outcome.

After a completed attack, up to 72 labeled tiles sit in a dark, bordered dice tray and show attack-count, hit, wound, save, damage, Hazardous and prevention dice. Each tile includes drawn D6 pips; the number and roll stage remain in text. Random characteristics show the underlying D6 faces and the resolver's converted attack/damage result separately. New result tiles can briefly tumble into place, with an **Animate new dice results** toggle to disable the motion. The animation reveals only the final values already resolved by the host; it never rolls separate visual dice. Final hit and wound faces show hit/wound, miss/fail or critical with a symbol, shape and color; replaced faces are omitted from this compact view but remain in the full recorded history. Save, attack-count, damage, Hazardous and prevention dice are not yet classified as success/failure. The selected model's overhead label adds OC, Battle-shock and movement cues; other models show wounds only. The presentation does not add random outcomes or alter host resolution.

The dice panel identifies whether results came from the local engine or LAN host, and shows the latest history entry containing recorded D6 plus a shortened current hash-chain tip. The battle log overlay also shows that chain tip, so the recorded sequence and dice can be inspected together. Tooltips expose the full tip and explain the boundary: loading a matching save verifies its committed journal prefix against record hashes and the saved state, which helps detect changes to that history. This is not an independent proof that the host RNG was fair or unpredictable; the host remains authoritative. A LAN client is directed to the host's match history rather than being shown a local chain it does not possess.

**Rules boundary:** hit and wound labels reuse the attack resolver's final dice and thresholds. Snap-shooting sixes are shown as hits, not critical hits, in line with the current 11e Core Rules. The pilot only labels critical thresholds currently represented by the resolver; special critical thresholds not implemented by the selected profile mechanics remain outside this display. These labels were checked against June 2026 11e Core Rules §§05.01–05.02 and Snap Shooting §15.09 at [Wahapedia](https://wahapedia.ru/wh40k11ed/the-rules/core-rules/) and cross-checked against the [official Games Workshop Core Rules PDF](https://assets.warhammer-community.com/eng_01-06_warhammer40k_new40k_core_rules-was6fbu1ix-hfewhmxyiy.pdf). This is presentation of the supported match engine's results, not a separate legality claim.
