# Gameplay UI

The game opens on a dedicated title screen over the existing 3D battlefield. Its primary action is **Start tactical training** when no compatible local save exists; a compatible save adds **Continue saved match**. The training summary shows both catalog-derived totals and offers **Swap training sides**. **New match** opens the existing setup flow. **Guide** opens a read-only field guide before a match; it explains the turn rail, controls, optional Keep-result and re-roll costs, the difference between source text and implemented scope, and offers the weapon ability glossary. **Results** opens a read-only list of result summaries explicitly saved on this computer, newest first. Search covers scenario, outcome, score, round, mission, scope and unit names; the selected summary can be copied. The browser distinguishes an empty folder, a location that cannot be opened and damaged or unsupported JSON files. It does not resume or change a match. **Settings** is also available before starting. Armies, Models and Tools remain available through secondary navigation when no match is active. During a match, the board is the primary workspace and contextual commands appear in a collapsible panel on its right edge. The menu, settings, help, mission overview and battle log open separate overlays.

## Title screen and combat HUD

With a model selected during a match, use the current Datasheet binding shown in Settings or activate **Datasheet** to open its read-only match profile. The shortcut is a named InputMap action; it is ignored while text fields, the title menu, a handoff or another tactical overlay has control.

While a tactical overlay is open, camera pan and focus shortcuts are suspended and keyboard input stays within that screen. Text entry, option pickers and focused lists also take priority over table shortcuts. Escape/Cancel closes the overlay; camera shortcuts work again after it closes. The local-player handoff and title menu also block board camera movement.

The interface uses 1920×1080 as its layout reference while preserving the project's 1280×800 initial window. The title screen is a Godot UI composition over the local procedural battlefield and any already imported local miniatures; it adds no generated artwork or model files. At launch, the menu intercepts board input. In a local match it also blocks board interactions while open. In LAN, opening the local menu does not pause or change the match state for either player.

The combat HUD stays above the board and remains fixed while details scroll. Its top bar is a turn rail: round and active player, then Command, Move, Shoot, Charge and Fight, with the current step marked. The line under the rail states who must act and the one thing to do. The compact score summary stays in the fixed HUD; below 1400 pixels wide it moves to the toolbar row with connection and local controls. When a mission uses objectives, **Mission** opens a read-only overview with score, the five most recent recorded scoring events in newest-first order, objective controller, the latest resolved P1/P2 Objective Control values and any active Vowed Target owner. It does not include provisional movement. Guided play adds a compact step counter; the decision line remains the instruction source. The selected-model summary sits below the scrollable army list as a compact footer. It shows unit name, selected model's ordinal/role, current/max wounds and a small wounds bar. Relevant exceptional conditions and movement/action context remain explicit. Characteristics, weapons and ability references are available through Datasheet in the local inspector. Source rules stay separate from implemented scope; incomplete local export relations carry a visible warning and can leave source ability entries missing. Viewing it changes no game state; closing returns to the same selection. The army list shows only the player who must act now, grouped by unit. Each unit row shows how many models are alive and whether the unit is Steady or Battle-shocked. Each model row uses a place name inside that unit, such as Model 1, plus current/maximum wounds, Reserves, or Destroyed. Sergeant is appended only for the one model that can use that unit's sergeant weapon options; the label does not change wounds or Battle-shock. Choosing a row selects that model, opens Command and frames the unit. Each unit has a control to hide or show its models, and Hide models does that for every unit. Hide closes the army list and the selected-model card; Army on the top bar brings that area back. Focus or the configured Focus binding does the same framing. The P1 side or P2 side control returns the camera to that player's table edge without forbidding orbit. P1 and P2 marks stay on those edges. The list does not spend an action or change wounds. The action panel on the right follows the current phase in its heading (Command, Movement, Shooting, Charge or Fight) and carries the current choices and results. During Inner Circle Task Force Command entry, the active decision owner gets an objective selector with a skip option; the Mission overview shows which player currently vows each objective. It can be hidden with the HUD button to expand the board view and opens again when a unit is selected. The army list stays up while Command is hidden. Short actions include Begin move, Confirm move, Plan attacks and Continue. Longer rule explanations stay in Help. Disabled choices retain the validator's explanation. Scope warnings remain available from the HUD tooltip.

Full profiles, equipment, ability effects, mission state, raw dice and technical session data remain accessible through tooltips, the technical-details foldout, completed result details, dice tray and Battle log. The attack forecast remains conditional and separate from resolved damage and recorded dice. The HUD only presents engine state; it does not alter validators, host authority or game state.

In local play, a change in decision owner opens a full-screen handoff for the receiving player. The first local state uses Player 1 as the seat that opened the match, so starting or resuming directly into a Player 2 decision opens the same handoff. The prompt names the receiving player and offers Continue as Player N; the decision stays hidden until they continue, and Escape cannot dismiss the handoff. After confirmation, focus moves to the current command controls. In LAN play, the non-owner continues to see the waiting state and does not receive the local handoff.

The title screen and in-match **Menu** both offer **Settings**. The in-match menu also offers **Return to current match** and **Save match**. Workshop and training tools are unavailable until leaving the match. Returning closes the local overlay and preserves the current phase, selection and command panel. LAN continues while any local screen is open. Settings gather window mode, resolution, interface size (100%, 110% or 120%), six remappable keyboard actions (Datasheet, Focus and four camera pan directions), model wounds/status markers, board/camera motion, decision framing and dice animation. Select a binding and press an unmodified key; if another listed action already uses it, those bindings swap. Reserved menu-navigation keys are rejected, and Escape cancels capture. Reset controls stages the defaults. Interface size scales the 2D controls and text while leaving the 3D tabletop at its current scale. **Apply** saves local preferences and activates staged bindings; **Revert** returns to the last applied values. The binding list scrolls while Apply/Revert remain available. Sound controls are not shown until the game has audio. Saved-match resume availability is computed by the normal save compatibility checks for configuration, rules/data pack, state structure and journal integrity; merely finding a save file does not enable Continue. If the primary snapshot is missing, corrupted or structurally invalid, the slot browser identifies the previous backup and its timestamp before the usual compatibility check. A recoverable backup is also called out under **Continue saved match** when it is the only local save. A save from a newer game version remains a compatibility error. The local save browser keeps selected-slot feedback separate from the current match's resumability notice, so an unassigned autosave warning does not hide whether a slot is empty, compatible or damaged.

The **Log** HUD button opens the persistent battle journal in a dedicated overlay. It retains the journal's paged events, state changes, results, per-model target assignments, attack pools and ordered D6 values with phase/player/revision context. This detail is reconstructed from the existing record patches; the save/journal format is unchanged. Closing it returns to the same match screen; viewing or paging sends no gameplay command. In LAN, the client reads pages from the host and the host remains responsible for saving. The dice tray labels faces as recorded D6 values; its brief reveal animates stored results and never creates a new roll.

## Guided first session (D1)

**Entry:** Title screen → **Start tactical training**. This starts the distinct [Fire and Manoeuvre / Close Assault forces](tactical-training.md) from the current local catalog; the player controls both sides. It uses the custom training mission, current unit abilities and admitted Core/Gladius stratagems. Optional phase tips and an experiment list point to leader abilities, CP stratagems, plasma/Hazardous and Bladeguard stance decisions without forcing a sequence. Automatic model downloads are off. It does not certify competitive balance, complete faction rules or army legality. The former 550-point mirror remains independently selectable.

| Moment | Player goal | In-game guidance and feedback |
|---|---|---|
| Mission setup | Resolve the selected mission's roll-offs and declarations | A compact HUD counter marks progress; the decision banner identifies the current choice and owner. Full step limits and term explanations are in Help. |
| Army setup | Confirm required leaders, Warlords, Support assignments and reserve declarations | Help explains the declarations and defines Leader, Warlord and Reserve. The next step stays gated until required choices are resolved. |
| Deployment | Place each unit and continue | Help explains the marked zone and preview positions. The board shows placement and count; incomplete or invalid placement cannot be confirmed. |
| Battle-start setup | Select a Terminator unit's optional Teleport Homer, set X/Z, confirm, or skip it | The guide states the marker → position → confirm sequence and offers **Finish start-of-battle declarations** to enter Command. |
| Movement | Select a friendly miniature, start a Normal move, reposition and confirm | The guide defines Normal move and confirmation, and states the boundary on legal movement. The decision banner and movement controls remain visible. |
| Shooting | Select a friendly unit, choose an eligible enemy, assign attacks and confirm | The guide defines eligible target and attack plan. Assignments are reviewed and validated before confirmation; the completed attack summary shows the result. |
| Charge | Select eligible targets, roll 2D6 and resolve any placement | The guide names the current charge task and waits on the existing target/placement decisions. |
| Fight | Follow the current pile-in, attack, reaction or consolidation step | The guide changes with the Fight step and points to the next required action. |
| End turn | Close the active player's turn and continue to the next player | The guide marks the first turn complete while the phase rail remains authoritative for later play. |
| Match end | Review the recorded result and history, or start another exercise | The guide offers the existing result and history paths. The sample does not certify full army legality or every rule. |

The step detail remains available in Help; the in-match HUD shows a compact guide counter next to the phase rail. Current ability-choice explanations remain visible in the Command panel during guided training. Phase progression and eligibility come from the match engine. Resuming the exact tactical formations restores contextual guidance from the saved phase, without storing a separate tutorial action sequence. Other matches retain their own configuration. The optional Homer step below applies to the former mirror and other Terminator exercises, not to the new tactical forces.

## Contextual weapon glossary

During an attack plan, hover a weapon/profile row or the selected profile control to read concise explanations for the profile's listed, recognized weapon abilities. The pre-match Guide and in-match Help tab both have a collapsed, keyboard-focusable glossary for every existing weapon ability entry, so players can browse those definitions without finding a weapon that uses them. Its text can be selected from the keyboard, and numeric values are shown in the selected profile's term and explanation. The target selector explains that its current choices passed the attack planner's checks; the Lethal Hits choice explains the automatic-wound trade-off. Hover a movement type to see its eligibility and consequences, including Advance, the two Fall Back modes and remaining stationary. The Begin and Confirm movement controls explain when positions are committed. Charge and Fight placement controls explain the 2D6 charge roll, selected targets, pile-in and consolidation limits. Hover the phase banner or progression control for the current phase's purpose and Core Rules section. In the supported Battle-shock and Command Re-roll windows, the unit, die, accept and stratagem controls explain their choices, CP cost and applicable limits. A circular arrow around a die marks available re-roll actions; the button text still names the action and cost. Disabled movement, contact, attack, defense and objective controls retain the validator's reason and add the applicable Core Rules reference where one is defined. Help names the relevant 11e Core Rules section and includes a link to the reference.

The glossary defines every keyword ID accepted by the current attack-profile validator, including Anti-X variants, Cleave, Indirect Fire, Melta, One Shot and Psychic. It covers the seven turn parts shown by this build, core movement/charge/Fight placement choices, selected blocked-action groups and supported core-stratagem decision windows. It explains source terms but does not claim that every effect is active in every match: match options and implementation scope still govern resolution. Keyword IDs outside the current validator, a complete unit-ability glossary and faction-stratagem help remain future work; each entry must match its selected Wahapedia 11e source/version and implemented capability boundary.

**Rules boundary:** summaries use the project's selected 11th-edition [Wahapedia Core Rules page](https://wahapedia.ru/wh40k11ed/the-rules/core-rules/), observed on 26 October 2026 with the page identifying the June 2026 Core Rules. Relevant references include §§01.07, 03, 04.01.03, 06.03, 07–12, 15.01–15.04 and 24.03–24.38. These summaries are informational and do not certify that every described effect is implemented. Older 10th-edition Insane Bravery timing is superseded and not used. Faction-stratagem help remains outside this scope until its current source is checked. Later source updates may change the version boundary.

## Contextual actions

During Command, doctrine abilities use separate action, unit and doctrine selectors. **Captain ability · 0 CP** exposes Strategic Acumen separately from **Adaptive Strategy · stratagem**. The preview shows the selected action's actual CP cost, doctrine effect, duration and current unit doctrine; an already-active primary doctrine receives a no-additional-effect notice. The confirmation button repeats the action and cost. Browsing never submits a command. Other available abilities remain accessible through their own category, and only existing legal choices are offered. This presentation does not change doctrine availability, cost, timing or eligibility.

Play groups controls into Movement/coherency, Charge/contact placement, Attacks, Resolve attack/damage, Objective actions and Phase progression. Groups with no relevant controls are hidden.

During an attack draft only its group is displayed, including Confirm and Cancel. Pending movement, contact placement, coherency removal and attack/Hazardous allocation focus the corresponding group until that decision finishes. Other groups return after the pending decision is resolved. This changes presentation, not host validation or the rules protocol.

Rejected placement shows the validator's reason beside the command controls and near the affected model. The action card identifies the red X, which remains at the rejected destination while the player previews another location; off-screen targets move to the nearest visible edge. When the affected model is outside the visible board area, the notice moves to the nearest board edge and names the direction; a model behind the camera is labeled. The board notice fits the available board area; if it cannot fit legibly, the complete reason and recovery remain in the command card while the destination marker stays visible when possible. The message offers a retry, while the original position remains governed by the authoritative movement check.

An unavailable action has a reason next to its group and on the disabled action's tooltip. Movement, attack planning, allocation and objective eligibility reuse rule validators. Charge/contact guidance follows the current eligibility checks. Completed exercises, missing peers and opponent-owned decisions identify the responsible state/player. Plan confirmation errors update as assignments change; a valid selection clears the old explanation. Available alternative actions in a group remain usable, for example declining Precision while no character is selected.

The **Direct Precision** button requires a selected character. A selection of -1 is reserved for the explicit **Do not use Precision** button, rather than accidentally accepting the decline through a button labeled as directing Precision.

## Guided attack and defense flow

Attack editing presents four steps: select a living model from the attacking unit; choose its weapon/profile, target and any fixed melee count; assign and repeat; review and confirm to roll dice. The review names the selected model/unit, counts assignments and distinct target units, and lists the resolution order from the first assignment to each target. Cancel discards the local draft. Weapon and target dropdowns preserve their selections on refresh and do not expand the sidebar to fit long names.

Pending Precision, defensive group order, damage and Hazardous choices show stage-specific instructions and the responsible player. Eligible-model choices use the roster ordinal, add Sergeant or Character where applicable, and show remaining wounds; the dropdown tooltip retains the full unit/model label. Selecting a card only changes board selection, and the confirmation button repeats the selected model before sending the existing command through host validation. For a selected damage recipient, the forecast applies supported damage reduction to the weapon's minimum/maximum before prevention and labels the value as a preview. It shows exact or possible remaining wounds only when the current damage range and applicable Feel No Pain rules permit that estimate; when prevention applies, it names the best target and leaves final wounds undecided. Reaching zero is labeled before any post-destruction effect. Returning to the prompt clears selection without declining Precision. The explicit decline button remains available for Precision; other required choices cannot be cancelled. Opponent-owned choices disable the picker locally. No save/damage rolls are exposed ahead of the existing rules sequence.

Six local suites passed for this increment: guided attacks, contextual action guidance, selection card, allocation practice, attack plans and mixed defenders. Tests check draft review without state changes, correct/incorrect model selection, named eligible choices, explicit confirmation, prompt reset, save timing guidance, opponent ownership and stale panel hiding. ## Track D3 presentation pilot

The board can show an optional compact Wounds bar above each living model, with current/maximum Wounds and the selected model's effective OC, Battle-shocked and movement state. The bar color is accompanied by exact numbers, and the toggle tooltip spells out its green/amber/red thresholds; color is not the only signal. The toggle hides these tags when the board is crowded. During an attack draft, the UI uses the same prepared attack batches as the resolver to show each pool's damage range if every declared attack becomes one unsaved wound. It labels this as a conditional scenario, before saves and prevention; critical or extra hits, failed hits/wounds, saves and damage prevention can change the result. It is not a probability estimate or a rules outcome.

The combat tray shows up to 72 labeled dice tiles for attack count, hits, wounds, saves, damage, Hazardous and prevention. Each tile includes drawn D6 pips; the number and roll stage remain in text. Revealed dice can be focused with the keyboard or clicked to show the full per-die description in a separate scrollable detail area. Activating a die moves focus into its description; use Up/Down, Page Up/Down, Home or End to read it, and Escape to return focus to the selected die. This inspects the recorded face and never submits a gameplay action. Before a face is revealed, its detail stays hidden. Changing stages returns the tray to the stage heading and first results. Random characteristics show the underlying D6 faces and the resolver's converted attack/damage result separately. Damage details connect a recorded random expression to its pre-prevention value and, when per-packet allocation data exists, the wounds applied, prevented and discarded. New result tiles can briefly tumble into place, with an **Animate new dice results** toggle to disable the motion. The animation reveals only values already resolved by the match; it never rolls separate visual dice. New hit, wound, save and Feel No Pain faces show ✓ or × alongside color, using the resolver's recorded per-die outcomes; critical hit and wound faces also show ★. This includes Anti-X critical wounds and the effective save thresholds used for each processed save, including AP, save modifiers and invulnerable saves. An unmodified 1 still fails. While a failed save waits for its recipient choice, processed dice receive markers and unresolved dice remain unclassified. Older saved results without outcome details retain raw hit, wound, save and Feel No Pain faces; the UI does not infer results from incomplete legacy records. Attack-count, damage and Hazardous dice remain raw because they do not use pass/fail outcomes. The selected model's overhead label adds OC, Battle-shock and movement cues; other models show wounds only. The presentation does not add random outcomes or alter match resolution. Keyboard focus, pointer behavior, contrast and panel fit still need Godot review.

The dice panel identifies whether results came from the local engine or LAN host, and shows the latest history entry containing recorded D6 plus a shortened current hash-chain tip. These labels were checked against June 2026 11e Core Rules §§05.01–05.02 and Snap Shooting §15.09 at [Wahapedia](https://wahapedia.ru/wh40k11ed/the-rules/core-rules/) and cross-checked against the [official Games Workshop Core Rules PDF](https://assets.warhammer-community.com/eng_01-06_warhammer40k_new40k_core_rules-was6fbu1ix-hfewhmxyiy.pdf). ## D4 camera focus pilot

The combat HUD offers **Focus** when a miniature is selected. Clicking it or pressing **F** eases the local camera toward the center of that miniature's visible unit. It uses the board positions already presented in the scene, keeps the current camera height, angle and zoom, and does not move models or submit a match action. The button is disabled without a visible selection. The same HUD names the current phase on the turn rail and states the next action in one line; Play then shows only that step's options. Automatic framing around the active decision and projectile tracers remain future D4 work.

With **Animate board feedback** enabled in Play, state changes can briefly ease a unit's models to their new positions, float a wound delta above a damaged or restored model, or mark a destroyed model as **OUT**. The toggle disables these presentation effects. Cues are derived from the resolved model state and do not perform dice rolls. Projectiles and attack impact flashes are not included yet. This increment has not been run in Godot; movement previews, reanimation, repeated damage and short-window readability still need live review.

A match opens looking from the local seat's side of the table: player 1 from that player's edge in a local or host game, and player 2 from that player's edge on a joined client. Orbit, pan and zoom remain available. P1 side or P2 side restores that seat's angle and the full table. The edge marks stay visible while the camera turns.

Decision camera: Help includes Auto-frame decisions and Animate board and camera. Supported unit/target changes frame living models in the board area outside the sidebar, HUD and right guide. Pan, orbit and zoom cancel automatic motion for that decision; selecting another model in the same unit or refreshing a placement does not restart it. F/Focus remains available with automatic framing disabled. Pan/zoom limits scale with board dimensions. This changes presentation only; it does not establish action legality.

Resolved attacks have optional, short schematic board feedback: a gold source-to-target arrow and an orange (damage applied) or pale cyan (zero damage) target ring. These summarize completed records, not ballistic paths, individual hits or visibility legality. They share Animate board and camera, expire after 0.8 seconds and do not replay on save restoration or ordinary refresh. Exact results remain in the existing result summary. Weapon-specific projectile/impact effects remain outside this pilot.

After the selected friendly unit has shot, Play replaces its stale attack options with a short completion marker. The HUD points to another unit or Continue to Charge, while the unit picker remains available. This confirms only that unit's recorded shooting action; it does not declare the phase complete or bypass attack eligibility checks.

Why unavailable? opens Help at its current-action blocker summary. It lists existing validator reasons for visible disabled actions, with rule references collapsed behind Show rule references and Back to Play above them. Hidden decision groups and stale selection reasons are excluded. This shortcut improves access without claiming complete rules-reference coverage.

Unit and mission choice details: ordinary choices show a compact selection/confirmation instruction in Play. Details for this choice opens Help at the full option name and existing explanation, preserving names truncated in the native picker. Active placement/healing, Bladeguard, wound decisions and Optics retain tactical instructions in Play. Reading details does not commit an action; stale descriptions clear when choices disappear.

The Help reroll selector also hides during the opponent's decision. Local play continues showing each side's choices as ownership changes. Empty choice lists clear stale option metadata and descriptions. Public board inspection/results remain available; network validation is deferred.

While waiting in LAN, Inspect your units lists the local player's living on-board units for read-only selection. The existing unit card and Focus/F support inspection without exposing opponent action controls. The picker is removed when the local player must decide; local mode retains the ordinary controls for both sides. No gameplay orders or plans are queued by inspection.

Its tooltip preserves the full text; View history opens the existing full reader in Help. The HUD separately names the pending decision. This reports recorded activity without implying real-time peer liveness, freshness or action completion beyond the event text.

## Ability rules in the datasheet

`Datasheet` shows each ranged or melee weapon profile as a wrapped name, a compact three-column grid labeled Range, Attacks, BS/WS, Strength, AP and Damage, then its keywords. This avoids a fixed-width weapon-name column pushing the inspector beyond the available sidebar width. When runtime scope entries exist, the inspector presents **Implemented Scope** before **Source Rules**, so the current match boundary appears before optional reference text. Source Rules includes the ability description, type and applicable model/parameter fields from the verified local Wahapedia 11e export, plus snapshot identity and retrieval date. A visible note states that source text is informational and does not confirm runtime support. Verified source entries start collapsed behind **Show source reference**; integrity errors and warnings start expanded, and reload feedback opens the section.

The reader prefers `user://rules/wahapedia/11e/space-marines/<snapshot-id>/`. A development checkout may use `.tools/wahapedia/11e/space-marines/<snapshot-id>/` only when no user snapshot is installed. The inspector checks the manifest's edition/source URL and SHA-256 for Datasheets.csv, Datasheets_abilities.csv and Abilities.csv, and reads it once when the inspector is first opened. Missing or mismatched sources produce an explicit message and retain the project-authored implementation scope. When source text is unavailable, **Open local reference folder** opens the `user://` parent folder for manual installation; it does not download data. If the operating system cannot open the folder, **Copy local reference folder path** copies its path for manual navigation. After copying or replacing a snapshot, select **Reload local reference** to read it immediately. HTML is converted to plain display text with headings and lists. Raw/derived third-party content remains local, outside Git, exports and peer snapshots; a standalone package without this local export shows the implementation scope, not the source descriptions.
